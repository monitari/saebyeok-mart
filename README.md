# 새벽 편의점

인도·차도와 주변 상가 4곳(영업시간에 따라 셔터·간판·창문 불빛이 바뀜), 주차장, 버스 정류장, 전봇대, 신호등, 편의점 기둥 간판·쇼윈도·파라솔 테이블, 가로수·화단·벤치·배수구·가로등이 있습니다. 하늘은 새벽·낮·노을·밤에 따라 바뀌고, 밤에는 가로등과 편의점 불빛이 거리에 번집니다. 게임 속 28일마다 계절이 바뀌며, 단풍·눈·젖은 도로·야간 조명이 반영됩니다. `매장` 확대와 `동네 전체` 보기로 전환할 수 있습니다. [주변 거리와 계절 안내](NEIGHBORHOOD.md).

공용 화장실과 디저트 냉장대, 상품 9종, 현금·카드 결제와 영수증을 추가했습니다. 가구·인물의 그리기 순서를 수정하고, 관계별 말투와 대사를 보강했습니다. 화면은 상황 카드·매장 관찰·운영 데스크 중심으로 개편했습니다. [매장 개편 안내](STORE_RENEWAL.md). 기존 세이브를 유지한 채 **Ctrl+F5**로 적용할 수 있습니다.

관계가 취식 자리와 일행을 기다리는 시간에 반영됩니다. 알바생은 능력·꼼꼼함에 따라 정리와 진열을 시작하는 시점이 다릅니다. 발주에는 즐겨찾기, 선택 상품 일괄 설정, 총액 미리보기, 추천 근거를 추가했습니다. [관계 행동·업무·발주 개선 안내](SOCIAL_WORK_UPDATE.md).

운영의 **변화** 탭에서 발주·시설 변경 이후를 확인할 수 있습니다. 현황 경고는 결정·대기·참고로 묶고, 복귀 시 부재중 정산과 실제 장면을 요약합니다. ATM만 쓰거나 가격을 둘러보고, 비를 피하거나 친구를 기다리는 방문도 추가했습니다. [운영 피드백·복귀 요약·방문 목적 안내](OBSERVATION_FEEDBACK.md).

운영 화면을 기본 패널로 바꾸고 자동·승인·수동 발주, 상품별 설정, 예산과 추천 주문서, 손님 부탁과 예약 재고, 업무 우선순위, 일일 마감과 동네 수요 변화를 연결했습니다. [운영 개편과 사용법](OPERATIONS_UPDATE.md)을 확인하세요. 기존 세이브를 유지한 채 새로고침하면 적용됩니다.

매장을 픽셀 쿼터뷰로 개편했습니다. 중앙 매대는 세로 통로형으로 바꾸고 창가 취식대, 낮게 잘라 낸 앞벽, 입구와 보도를 입체적으로 그립니다. 기존 커피·택배·주류·분리수거·셀프 계산·곤란한 손님 기능은 유지합니다. [배치와 그래픽 변경 내역](QUARTER_VIEW.md)을 확인하세요. 실행 중인 화면을 새로고침하면 적용됩니다.

새 게임은 목요일 밤 21:18의 시작 화면에서 출발합니다. `이 밤 들여다보기`를 누르기 전에는 시간이 흐르지 않습니다. 알바생, 실제 장면, 그 일의 기억을 살펴보는 짧은 안내를 제공하며 `안내 없이 시작`도 가능합니다. 기존 세이브는 그대로 이어지고, 설정의 `관찰 안내 다시 보기`로 안내만 열 수 있습니다.

거리 풍경, 관계 구분, 기억 융합 패치를 적용했습니다. [변경 내용과 동작 방식](PATCH_LIVING_WORLD.md)을 확인하세요. 실행 중인 게임을 새로고침하면 적용되며 기존 세이브를 이어 쓸 수 있습니다.

v0.3의 전체 개선 내역과 검증 한계는 [IMPLEMENTATION_REVIEW.md](IMPLEMENTATION_REVIEW.md)에 있습니다. 서버 코드가 바뀌었으므로 기존 서버를 종료한 뒤 `start.cmd`를 다시 실행하세요.

## 화면 사용

- `관찰 모드`로 인물과 기록 패널을 접어 매장을 크게 볼 수 있습니다. 같은 버튼으로 돌아옵니다.
- 카메라 버튼은 매장 아래에 있습니다. 확대 배율, 전체 보기, 인물 따라가기를 제공합니다. 확대는 픽셀이 깨지지 않도록 ×1, ×2, ×3 같은 정수 배율로만 바뀝니다.
- 현재 매장 안 사람을 먼저 보여주고, 다녀간 사람은 접힌 목록에서 찾습니다. 인물 정보는 최근 기억을 우선 보여주며 `매장에서 찾기`, `이 사람의 대화`로 바로 이동합니다.
- 대화 기록을 위로 스크롤하면 자동 이동이 멈춥니다. `새 대화 N개` 또는 `최신 대화로`를 누르면 다시 따라갑니다. 날짜와 시간으로 지난 대화를 구분합니다.
- 장면 카드의 점과 장면 탭의 숫자는 아직 안 본 기록입니다. 사건 패널에서 진행 중인 장면과 기록된 부분의 다시 보기를 함께 찾을 수 있습니다.
- 모바일은 실제 상단바 높이와 화면 높이에 맞춰 매장 공간을 배분합니다. 사람을 누르면 정보 시트가 열리고, `매장에서 찾기`를 누르면 시트를 접고 따라갑니다.
- 발주 수량이나 근무표를 입력하는 동안에는 해당 폼을 자동으로 다시 그리지 않습니다. 인물 상세에서 펼친 항목도 상태 갱신 중 유지합니다.

키보드로 탭 메뉴에 접근한 뒤 좌우 화살표와 Home/End로 이동할 수 있습니다. 설정은 보기 중 영업을 잠시 멈춥니다.

## 장면 알림과 다시 보기

중요한 교환이나 사건이 생기면 매장 아래에 작은 알림이 뜹니다. `지금 보기`는 관련 인물로 카메라를 이동시키고, 끝난 장면의 `다시 보기`는 기록된 위치·동작·대사를 별도 창에서 재생합니다. 설정에서 자동 카메라 이동을 켤 수 있으며 기본은 꺼짐입니다. `장면 모아보기` 또는 사건 패널에서 최근 장면을 다시 열 수 있습니다.

최근 8개 장면과 간직한 장면 최대 4개에 각각 최대 40프레임과 실제 대사 24줄을 보관합니다. 게임 시간 0.5분 간격의 짧은 동작 기록으로, 사건 직전 2분과 대화 종료 뒤의 짧은 구간을 포함합니다. 모델 대기 중에는 같은 정지 자세로 프레임을 채우지 않습니다. 재생/일시정지와 슬라이더를 지원하며, 재생 중에는 영업이 멈춥니다. 과거 대사를 새로 생성하거나 거래와 관계 변화를 다시 실행하지 않습니다.

장면은 당시 외형까지 자동 저장과 내보내기에 포함됩니다. 기존 버전 2 세이브도 읽으며 업데이트 이전 장면은 소급 생성하지 않습니다. 열람 여부는 NPC의 지식이나 기억에 영향을 주지 않습니다. 담배는 발주와 시설에서 판매대를 설치한 뒤 상품을 발주해 사용할 수 있습니다.

작은 동네 편의점에서 알바생과 손님이 생활하고, 짧게 말을 주고받고, 지난 만남을 기억하는 모습을 지켜보는 관찰형 방치 웹게임입니다.

## 실행

Node.js 22 이상이 필요합니다. 설치할 패키지는 없습니다.

```sh
npm start
```

브라우저에서 http://127.0.0.1:4173 을 엽니다. Windows에서는 `start.cmd`를 실행해도 됩니다. PowerShell 실행 정책 때문에 `npm`이 막히면 `npm.cmd start`를 쓰세요.

`dist/`만 정적 호스팅해도 게임은 돌아갑니다. 다만 아래의 로컬 모델 프록시(`/local-ai`)는 `server.mjs`로 실행할 때만 있습니다.

## GitHub Pages에 올리기

`.github/workflows/pages.yml`이 `main` 브랜치에 푸시될 때마다 문법 검사와 테스트를 돌리고, 통과하면 `dist/`만 Pages에 올립니다.

1. GitHub에 저장소를 만들고 이 폴더를 `main` 브랜치로 푸시합니다.
2. 저장소의 Settings > Pages에서 Source를 `GitHub Actions`로 고릅니다.
3. Actions 탭에서 배포가 끝나면 `https://아이디.github.io/저장소이름/`에서 열립니다.

Pages에서는 방문자마다 자기 브라우저에 따로 저장되고, 대사는 기본으로 규칙 기반입니다. 모델을 쓰려는 방문자는 자기 컴퓨터에서 Ollama를 실행하고, 이 페이지의 출처를 허용해야 합니다. 출처에는 경로 없이 `https://아이디.github.io`만 넣습니다.

```powershell
setx OLLAMA_ORIGINS "https://아이디.github.io"
```

그다음 Ollama를 완전히 종료했다가 다시 켭니다. 게임 설정의 서버 주소는 `http://127.0.0.1:11434`입니다(Pages에서 열면 이 값이 기본으로 들어갑니다). Chrome은 공개 사이트가 내 컴퓨터의 서버에 접근할 때 허용 여부를 물을 수 있으니 허용을 누르세요. 요청은 방문자 자신의 컴퓨터로만 가고 외부로 나가지 않습니다. 같은 `아이디.github.io` 아래의 다른 페이지들과 브라우저 저장소 출처를 공유하므로, 세이브 이름은 `saebyeok-mart`로 구분합니다.

## 조작

- 상단: 날짜와 시간, 날씨, 오늘 매출과 금고, 일시정지(Space)와 1, 3, 8, 20배속. 기본 1배속에서 1초는 게임 속 1분이며 설정에서 시간 흐름을 바꿀 수 있습니다.
- 매장: 사람을 누르면 오른쪽에서 살펴봅니다. 진열대, 냉장고, 전자레인지, 우산꽂이, 입고 박스를 누르면 재고와 상태가 보입니다. 휠이나 핀치로 확대하고, 확대한 상태에서는 끌어서 이동합니다. `따라가기`를 켜면 선택한 사람을 화면이 따라갑니다.
- 오른쪽 운영 패널: 현황, 재고·발주, 시설, 업무. 상단에서 발주 모드를 바꾸고, `넓게 보기`로 주문서를 크게 검토합니다. 사람을 누르면 인물 정보로 전환되고 `매장 운영`으로 돌아옵니다.
- 매장 아래: 최근 대사를 짧게 보여줍니다. 전체 대화 기록, 사건, 근무표는 필요할 때 서랍을 엽니다.
- 모바일: 매장이 화면 폭을 채우고 확대된 상태로 시작합니다. 아래 시트의 운영, 사람, 대화, 장면, 근무 탭에서 정보를 봅니다.

처음 몇 분 동안의 장면은 정해 두었습니다. 비 오는 밤에 친구 둘이 장을 보고 있고, 우산 없는 배달 기사가 들어옵니다. 그 뒤로는 규칙에 따라 장면이 생깁니다.

처음 12분의 게임 시간에는 일반 손님이 한꺼번에 밀려들지 않도록 간격을 뒀습니다. 근무 시작은 실제 근무표의 14:00으로 맞추고 유나의 피로도도 반영합니다. 동창, 가족, 동료 관계와 자기 취향은 `이미 알고 있던 사실`로 시작하며, 과거 방문·매출·약속을 가짜로 만들지는 않습니다. 새 게임의 기본 동네는 같은 시드로 시작합니다.

## 구현된 것

**매장과 그래픽.** 32픽셀 타일로 된 매장 하나입니다. 우유와 음료 냉장고, 도시락 냉장 매대, 과자와 라면과 생활용품 진열대, 계산대와 POS, 전자레인지와 온수기, 취식대, 쓰레기통, 창고 문, 입고 박스 자리, 우산꽂이, 출입구, 매장 앞 거리가 있습니다. 진열 수량은 실제 재고에 따라 줄고, 다 팔리면 빈자리와 붉은 가격표가 남습니다. 전자레인지는 쓰는 동안 불이 켜지고, 먹고 난 자리에는 쓰레기가 남을 수 있습니다. 비 오는 날에는 입구 바닥이 젖어 알바생이 닦습니다. 입고 박스는 팔레트에 쌓였다가 진열로 옮겨집니다. 낮과 밤에 따라 거리 밝기가 바뀌고, 날씨는 맑음, 흐림, 비, 거센 비 사이에서 바뀝니다.

인물은 32x48 틀 안에서 몸, 하의, 상의, 팔, 머리, 머리카락, 소품을 조합해 그립니다. 대각선을 포함한 여덟 방향과 걷기, 대기, 둘러보기, 집기, 계산, 먹기(앉기), 걸레질, 박스 나르기 동작이 있습니다. 1픽셀 외곽선을 두르고, 아이, 청소년, 성인, 노인과 체형 넷이 실루엣으로 구분됩니다. 앞뒤 순서는 발 위치로 정하고, 높은 진열대 뒤에 선 사람이 있으면 그 부분만 진열대를 반투명하게 그립니다.

**매장 내부 설비.** 장식으로만 있는 설비는 거의 없고, 대부분 상태가 있어 손님과 알바생의 행동에 연결됩니다.

운영에서는 상품별 1+1, 2+1 행사를 걸 수 있습니다. 행사 상품을 집으면 덤을 같이 가져가고, 행사 상품을 찾아오는 손님이 늘지만 공짜로 나간 만큼 매출은 줄어듭니다. 저녁 8시에는 알바생이 다음 날 아침 폐기될 상품에 30% 할인 스티커를 붙이고, 예산이 빠듯하거나 실속을 챙기는 손님이 그 상품을 먼저 집습니다. 손님이 상품을 고를수록 진열이 흐트러지고, 한가한 알바생이 다시 정리합니다. 흐트러진 정도는 화면에서 삐뚤어진 상품으로 보입니다. 충동구매는 그 손님이 원래 가려던 진열대 근처에서만 일어납니다. 운영 패널의 "매장 상태"에서 쓰레기통, 진열 정리, 원두, 장바구니, 택배, 스티커를 숫자로 볼 수 있습니다.

**까다로운 손님.** 진상 행동은 정해진 인물이 하는 대본이 아니라 성격 수치와 그날의 상태(술, 통화, 배고픔, 습관)에서 나옵니다. 같은 사람이 같은 일을 반복하지 않도록 사람마다 쿨다운이 있고, 매장 전체로는 하루 5건까지만 일어납니다(취한 상태는 사건이 아니라 상태라 이 수에 들어가지 않습니다).

겪은 알바생은 그 손님을 "주의 손님"으로 기억합니다. 기억하는 알바생은 다음에 더 단호하게 대응하고, 그냥 나가려는 사람도 더 잘 알아챕니다. 교대 때는 "용수 손님이 집 쓰레기를 버리고 갔어요"처럼 실제 있었던 일로 넘깁니다. 넘겨받지 못한 알바생은 모릅니다. 곁에서 본 손님 중 꼼꼼하거나 다정한 사람은 기억에 남기고, 매장 평판이 조금 내려갑니다. 불만은 날마다 가라앉고, 사과하면 풀립니다. 운영 패널의 "알바생들이 기억하는 주의 손님"에서 각 알바생이 실제로 아는 것만 볼 수 있습니다.

새로 온 사람은 회식이 잦은 영업 과장 태식, 통화하며 다니는 직장인 민혁, 따질 건 따지는 혜숙, 은퇴한 교장 만호, 그리고 같이 다니는 중학생 준서, 서진, 도현입니다. 이전 세이브에서는 이 사람들이 처음 보는 사람으로 등장하고, 지어낸 과거 기억은 없습니다.

**인물 데이터.** 알바생 3명과 고정 손님 21명이 있고, 새 게임의 시드로 동네 손님 6명을 더 생성합니다. 각 인물은 다음을 따로 저장합니다.

- 외형 유전자: 시드, 생성 결과, 호환 보정 기록, 데이터 버전. 부품마다 맞는 연령대와 체형이 정해져 있어서, 맞지 않는 조합(예: 아이에게 긴 코트나 지팡이)은 다른 부품으로 바뀌고 그 사실이 기록됩니다.
- 성향 유전자 8가지, 표현 성향(말의 길이, 말투, 직설성, 말 거는 빈도, 몸짓), 생활 정보(연령대, 배경, 방문 시간대, 예산, 선호 상품, 모임).
- 현재 상태(피로, 배고픔, 급함, 기분, 지금 하는 일), 기억, 방향이 있는 관계(친밀, 신뢰, 고마움, 불만).

외형과 성격은 따로 만듭니다. 험상궂은 공사 반장 만식은 손님 중 가장 친절한 편이고, 상냥한 말투의 학원 원장 서윤은 할인이나 새치기를 부탁합니다.

**성격이 행동을 바꾸는 곳.** 참을성이 낮으면 줄에서 재촉하고 오래 기다리면 그냥 나갑니다. 자기중심성이 높으면 새치기를 시도합니다. 꼼꼼하면 오래 고르고 쓰레기를 직접 버립니다. 충동성이 높으면 계획에 없던 것을 집고 품절일 때 다른 것을 고릅니다. 사교성은 대사 길이가 아니라 말을 거는 빈도로 나타납니다. 알바생의 직설성은 재촉과 새치기에 대한 대응을, 친절함은 우산을 먼저 권할지를, 능력치는 계산, 진열, 청소 속도를 바꿉니다.

**방문과 일행.** 개인, 관계, 고정 모임, 이번 방문의 실제 일행, 현재 대화 참여자를 나눠 둡니다. 친구 셋 중 둘만 오기도 하고, 동료와 오던 사람이 혼자 오기도 합니다. 일행이어도 각자 고릅니다. 아빠가 아이 것까지 계산하는 방문, 각자 계산하는 방문이 있고, 먼저 끝낸 사람은 안이나 밖에서 기다립니다. 계산 줄과 서 있는 자리는 한 사람씩 예약하고, 같은 칸에 겹친 사람은 그릴 때 옆으로 비켜 그립니다. 오래 움직이지 못하면 경로를 다시 찾습니다.

**알바생과 근무표.** 요일별 기본 근무(오전, 저녁, 야간)에 날짜별 예외(대타, 휴가, 지각, 연장 근무)를 더합니다. 다음 알바생이 늦으면 앞사람이 그만큼 더 일합니다. 교대할 때 나가는 알바생은 중요한 일을 1~3가지만 말로 넘깁니다. 꼼꼼한 사람일수록 많이 넘깁니다. 넘겨받지 못한 일은 새 알바생이 모릅니다. 그래서 따로 빼 둔 상품이 있어도 모르는 알바생은 꺼내 주지 못합니다. 매장 평판과 특정 알바생에 대한 관계는 따로 계산합니다.

**사건과 기억.** 사건 원본에는 무슨 일이 있었는지, 누가 근처에서 보고 들었는지가 남습니다. 각 인물의 기억은 그 사람이 본 대로 따로 쓰입니다. 같은 재촉 장면을 보고도 다정한 사람은 "많이 급해 보였다"로, 의심 많은 사람은 "불편했다"로 기억합니다. 해석이 원본을 바꾸지는 않습니다. 기억에는 사건 ID, 대상, 게임 시간, 중요도, 출처(직접 봄, 전해 들음, 인수인계, 반복 경험), 해결 상태가 있습니다. 반복 구매는 하나씩 쌓지 않고 "주로 캔커피를 산다" 같은 습관으로 합칩니다. 빌린 우산, 대신 내 준 돈, 발주 약속처럼 미해결인 일은 오래되어도 지우지 않습니다. 일행끼리도 모든 것을 공유하지 않습니다. 대화로 전한 내용만 그 자리에서 들은 사람에게 전해 들은 기억으로 남습니다.

기억이 행동을 바꾸는 예는 다음과 같습니다. 빌린 우산은 다음 방문 때 돌려줍니다. 친해진 알바생에게는 먼저 인사합니다. 지난번 품절된 상품을 다시 찾고 물어봅니다. 언쟁 뒤에는 사과하거나 평소처럼 인사하며 풀고, 불만은 날마다 줄어듭니다. 라면값을 대신 내 준 사람을 다시 만나면 인사합니다. 알바생은 자주 오는 손님이 주로 사는 것을 알아봅니다.

**경영.** 상품별 진열, 창고, 주문 중 수량과 기준 재고가 있습니다. 새벽 3시에 자동 발주하고 아침 7시에 입고됩니다. 직접 발주도 할 수 있습니다. 유통기한이 있는 상품은 폐기됩니다. 취식대를 하나 더 놓으면 먹고 가는 손님과 쓰레기가 늘고, 비닐우산을 들여놓으면 비 오는 날 사 가는 손님이 생깁니다. 인기 상품이 자주 품절되면 같은 손님이 다시 묻습니다. 그때 실제로 발주가 가능할 때만 "내일은 하나 더 시켜 둘게요"라고 약속하고, 약속한 수량은 입고 때 따로 빼 둡니다. 금고, 매출, 발주는 하나의 장부로 맞춥니다.

**저장.** IndexedDB에 메타, 매장, 인물, 관계, 기억과 사건, 대화 기록을 조각으로 나눠 한 트랜잭션으로 씁니다. 조각마다 같은 리비전 번호를 붙여, 읽을 때 서로 맞지 않으면 예비 저장으로 넘어갑니다. 계산이 끝날 때, 미해결 일이 생기거나 풀릴 때, 교대 때, 그리고 20초마다 저장합니다. 탭을 숨기거나 닫을 때도 저장합니다. 저장 실패는 상단 칩과 안내로 알리고 파일 내보내기를 권합니다. 내보낸 파일을 가져올 때는 구조, 값의 범위, 인물 ID 참조, 이동 경로가 벽을 지나지 않는지를 검사합니다. 이전 프로토타입(세이브 버전 1)의 브라우저 저장이나 파일은 버전 2로 옮깁니다. 화면의 대화 기록(최근 300줄)과 인물의 기억은 따로 관리합니다.

## AI 연결 상태

**기본은 규칙 기반이며 로컬 모델 연결을 선택할 수 있습니다.** v0.3에서 실제 Ollama `qwen2.5:3b`로 생성 및 게임 적용을 확인했습니다. 대화 기록에는 규칙/AI/대체 출처가 표시됩니다. 생성 성공이 의미 품질을 보장하지는 않으므로 자동 검사와 규칙 대체를 유지합니다.

게임 규칙이 돈, 재고, 이동, 구매, 계산, 시간, 사건과 거래 선택을 확정합니다. 모델은 인사와 잡담의 표현을 맡으며 검증된 예시의 의미를 유지해야 합니다. 입력은 일부 성향과 상태, 상대, 장면, 최근 4줄, 관련 기억 3개, 미해결 약속 2개와 이미 결정된 행동 ID로 제한합니다. 가격·우산 반납·입고 약속·신분 확인 같은 사실 전달은 규칙 대사를 사용합니다.

연결해 보려면:

1. Ollama를 설치하고 모델을 받습니다. 이번 검증 모델은 `qwen2.5:3b`입니다. `ollama pull qwen2.5:3b`
2. `npm start`로 게임을 엽니다. 서버가 `/local-ai` 아래 요청을 `http://127.0.0.1:11434`로 넘겨 주므로 CORS 설정이 필요 없습니다. 다른 주소를 쓰려면 `LOCAL_AI_TARGET`을 지정합니다. 루프백 주소만 허용합니다.
3. 설정에서 `로컬 서버: Ollama`, 주소 `/local-ai`를 선택하고 `모델 목록`, `대사 생성 시험`, `적용` 순서로 확인합니다.

LM Studio처럼 OpenAI 호환 API를 쓰는 서버는 `로컬 서버: OpenAI 호환`과 `/local-lm`을 선택합니다. 로컬 게임 서버가 기본 `127.0.0.1:1234`로 전달합니다. 다른 포트는 `LOCAL_LM_TARGET`으로 지정하며 루프백만 허용합니다. 정적 호스팅에서 직접 접속하는 경우에는 모델 서버의 출처 허용 설정이 필요합니다.

모델 호출은 한 번에 하나, 요청당 현실 시간 8초이며 형식이 틀리면 한 번만 다시 묻습니다. 게임 쪽 전송 요청 예산은 현실 시간 8.5초로 배속과 독립적입니다. 미전송 대기열은 짧은 게임 시간 기한 후 규칙 대사를 사용합니다. 설정·일시정지·다시 보기·숨김 중에는 응답 적용을 보류하며 모델 설정/세이브 변경 시 이전 요청을 취소합니다. 늦은 응답과 퇴장한 인물의 응답은 버립니다. WebGPU 브라우저 내 추론은 구현하지 않았습니다.

## 규칙 기반 대사가 상황을 반영하는 방식

AI 없이도 같은 손님이 매번 다르게 말하도록, 대사를 고를 때 그 순간의 사실을 봅니다(`dist/dialogue-data.js`의 `CONTEXT`, `dist/sim.js`의 `factsFor`). 선택 로직은 `dialogue.js`에 있습니다.

- **조건이 맞는 대사 중 가장 구체적인 것.** 날씨, 시간대, 관계 단계, 며칠 만인지, 지난번 날씨, 지난 구매, 품절됐던 상품을 이번에 샀는지, 일행 없이 혼자 왔는지 같은 조건을 대사에 붙여 둡니다. 맞는 조건이 많은 대사를 먼저 고르고, 특정 인물의 대사는 더 우선합니다. 아무것도 맞지 않으면 일반 대사를 씁니다.
- **아는 것만 말하기.** 알바생은 자기가 직접 본 방문으로만 "며칠 안 보이셨네요"나 "오늘은 비가 그쳤네요"를 판단하고, 습관을 알아챈 손님에게만 "늘 사시는" 이야기를 합니다.
- **관계 단계.** 손님과 알바생은 계산할 때마다 조금씩 가까워집니다(처음 본 사이, 얼굴만 아는 사이, 단골, 친한 사이). 단계에 따라 먼저 인사할지, 누가 먼저 말을 걸지, 계산대에서 잡담을 할지가 바뀝니다.
- **잡담은 주제를 이어 갑니다.** 알바생이 "퇴근하시는 길이에요?"라고 물으면 대답도 그 주제에서 고릅니다. 배달 기사 도윤은 "아니요, 이제 시작이에요."라고 답합니다.
- **말버릇.** 인물마다 짧은 대답 습관이 표현 유전자에 있습니다(도윤 "아 네네.", 서윤 "어머, 네."). 생성된 손님도 시드로 정해집니다.
- **반복 피하기.** 같은 사람에게 같은 말을 이틀 안에 다시 하지 않고, 상황에 맞춘 말은 두 시간 안에 다른 사람에게도 되풀이하지 않습니다. 남은 말이 모두 겹치면 잡담은 아예 하지 않고, 꼭 필요한 말(가격 안내 등)만 그대로 합니다.

화면에는 이 대사들도 모두 `규칙`으로 표시됩니다.

## 대사 규칙

출력 형식과 코드 검사를 함께 씁니다(`dist/lint.js`). 한 발화는 1~2문장, 60자 이하입니다. 가운뎃점, 불릿, 괄호, 별표, 따옴표, 이모지, 반복 문장부호, 말줄임표 남용, 내면 독백, 감정 서술, 서술형 어미, 교훈조 표현을 막습니다. 같은 대화 안의 반복과, 맥락에 없는 숫자나 상품 이름도 막습니다. 평범한 계산은 말없이 끝나거나 두세 마디로 끝납니다. 대화마다 줄 수와 시간에 상한이 있고, 말할 필요가 없으면 아무 말도 하지 않습니다.

## 구조

| 파일 | 맡은 일 |
| --- | --- |
| `dist/sim.js` | 시간, 방문, 손님과 알바생 행동, 계산, 재고와 돈, 교대, 대화 진행, 모델 응답 재검증 |

| `dist/genes.js` | 외형과 성향 생성, 부품 호환 규칙, 외형 라벨 |
| `dist/roster.js` | 근무표와 예외 계산 |
| `dist/dialogue.js`, `dist/lint.js` | 규칙 대사 문장과 대사 검사 |
| `dist/ai.js` | 모델 어댑터, 대기열, 시간 제한, 재시도 |
| `dist/save.js` | 세이브 형식, 검증, 마이그레이션, IndexedDB |
| `dist/art.js` | 픽셀 렌더링 |
| `dist/interior.js` | 매장 설비 상태, 행사와 할인 스티커 가격, 알바생의 정리 업무, 택배 기사와 수거차, 설비 저장 검증 |
| `dist/nuisance.js` | 까다로운 손님의 행동, 알바생 대응, 주의 손님 기억, 하루 상한과 쿨다운 |

그리기는 매 프레임, 시뮬레이션은 게임 시간 0.1분 단위, 패널은 0.25초마다 바뀐 것만 다시 만듭니다. 모델 설정은 브라우저 localStorage에, 게임 기록은 IndexedDB에 따로 둡니다.

## 검증

```sh
npm test        # 73개 시나리오 (매장 설비는 tests/interior.test.mjs, 까다로운 손님은 tests/nuisance.test.mjs)
npm run check   # 문법 검사
```

자동 테스트가 확인하는 것:

- 성미 급한 손님이 줄에서 재촉하고 알바생이 짧게 답한다. 비 때문에 우산을 빌리고 미해결 일로 남는다.
- 그 손님이 나중에 와서 우산을 돌려주고, 사건과 관계가 갱신된다. 그 자리에 없던 사람은 반납을 모르고, 빌려준 알바생이 없었다면 그 사람은 아직 빌려준 상태로 기억한다.
- 교대 때 넘긴 일만 다음 알바생이 알고, 손님 응대 대사는 근무 중인 알바생만 한다.
- 개인과 일행이 사고 계산하고 나간다. 사흘 동안 재고 대조와 금고 장부가 맞는다.
- 인물이 진열대나 계산대 안에 들어가거나 걷다가 멈춰 있지 않다.
- 기억은 목격, 전해 들음, 인수인계에서만 생긴다. 이름은 들은 사람만 안다.
- 계산 도중 저장하고 복원해도 그 뒤 1,500분이 원래와 똑같이 진행되고, 한 계산이 두 번 청구되지 않는다.
- 모든 문장과 이틀 치 대사가 길이와 표기 규칙을 지킨다.
- 발주가 불가능하면 발주 약속을 하지 않는다.
- 모델 응답이 없거나, 늦거나, 규칙을 어기거나, 제시하지 않은 행동을 골라도 게임이 멈추지 않는다.
- 일주일을 돌려도 기록, 사건, 기억, 대기 작업이 상한 안에 있다.
- 잘못된 세이브를 거부하고, 이전 프로토타입의 실제 세이브를 옮긴다.
- 근무표의 대타, 지각, 휴가 계산이 맞고, 유전자 생성이 재현되며 부품 호환이 지켜진다.
- 상황에 가장 구체적으로 맞는 대사가 골라지고, 알바생은 자기가 본 방문만 언급하며, 일주일 동안 단골 관계가 생기고 같은 사람에게 같은 말을 되풀이하지 않는다.

현재 화면은 격리된 Chrome에서 PC 1440×1000과 모바일 390×844로 확인했습니다. 발주·시설·저장·매장/동네 보기 조작과 콘솔 오류를 검사하며, 계절별 렌더링 이미지도 `reports/neighborhood-*.png`에 저장합니다. 이전 기능별 검증 기록은 `reports/`와 `IMPLEMENTATION_REVIEW.md`를 참조하세요.

## 아직 구현하지 않은 것

- 브라우저 내 직접 추론, 실제 LM Studio 서버 검증
- 부재중 관계 장면과 배송 진행(지금은 재고 판매와 매출만 정산)
- 진열 위치 변경, 알바생 채용과 개별 급여(지금은 하루 운영비로 단순화)
- 손님이 다른 손님 이름을 대화로 알게 되는 경우 외의 소개 장면, 손님끼리의 오래가는 갈등
- 알바생이 근무 밖에 손님으로 오는 장면
- 걷는 동안의 실시간 충돌 회피(지금은 서 있는 자리 예약과 그릴 때 비켜 그리기로 처리)
